# Concentration thresholds — integrating the Atamai ceilings (proposal)

**Status:** proposal for expert review — nothing here is signed off or implemented.

Atamai Analytics have shared a per-analyte **maximum plausible value** table
(`AtamaiAnalyticsAnalytePlausableValues.xlsx`, received 2 Sep 2026; preserved at
`com.lithodat.ai.hannelore/project/lithosurfer/data-qa/`). It is philosophically
different from the circulating [GC Upload Rules](thresholds.md) — and mostly
**complementary rather than competing**. This page sets out how the two fit
together, where they clash, and what needs an expert decision before anything
is implemented.

| | |
|---|---|
| Circulating rules | [Concentration thresholds](thresholds.md) — warning/fatal per analyte (Aug 2026 draft) |
| New input | Atamai *Analyte Plausible Values* — one ceiling per analyte, derived from ore-mineral stoichiometry |
| Companion checks | [Quality checks](quality-checks.md) — sentinels, closure, spectrography, flag-don't-fix |
| Full comparison tables | generated by `compare-atamai-vs-gc-rules.js` (see appendix section below) |

---

## What the Atamai table is

131 rows covering 78 elements, 40 oxides and a handful of mineral-form analytes
(`MoS2`, `CaCO3`, `FeCO3`, `MgCO3`, `MnCO3`, `YFe3`…). Each row carries:

- `plausible_max_value` + `plausible_max_unit` — a **ceiling**, not a warning band;
- a mineralogical justification for every number (e.g. *"Galena (PbS) = 86.6% Pb;
  cerussite = 77.5% Pb; massive Pb ore"* → Pb ceiling 870,000 ppm);
- for 12 analytes an `pct_ore_grade_threshold` (0.01–50 %): the level above which
  the value is read as **ore-grade material**, flagged as such rather than as an error.

The ceilings are almost all **mineral-formula bounds**: the maximum that analyte
can reach if the sample were pure ore mineral. The intent is clearly
*"physically impossible above this"* — the same role as LithoSurfer's existing
fatal ceiling, but derived from mineral chemistry instead of a round 1,000,000 ppm.

---

## How the two tables differ — and why that is useful

| | GC Upload Rules (circulating) | Atamai ceilings |
|---|---|---|
| Purpose | two-sided QC gate: **warning** band + **fatal** ceiling | single **plausibility ceiling** (plus ore-grade marker) |
| Derivation | expert judgement, partly arbitrary (e.g. Fe warn at 5.5 wt%) | mineral stoichiometry (galena, sphalerite, monazite…) |
| Coverage | 118 elements + 94 oxides incl. synthetic fillers | 78 elements + 40 oxides, real geology only |
| Low side | 11 warning lows (unit-error traps) + fatal `< 0` | none — high side only |
| Semantics | warning = review; fatal = block upload | ceiling = not physically possible |

Three observations drive the proposal:

1. **The two tables answer different questions.** The GC rules ask *"is this
   number surprising?"* (warnings). Atamai asks *"is this number possible?"*
   (ceilings). A warning band cannot be derived from a ceiling, and vice versa.
2. **Atamai directly fixes the noisiest draft rules.** Fe warn-high 55,000 ppm
   flags every basalt; the Atamai Fe ceiling is 900,000 ppm (magnetite ~72 % Fe).
   The draft review on [thresholds](thresholds.md) asked exactly for this
   (question 1: raise Fe to 15–20 wt%); Atamai goes further and grounds it.
3. **Atamai has no low side at all.** The unit-error traps (Si < 50 ppm, Al < 55,
   wt% left unconverted) and the `< 0` fatal are absent — those must keep coming
   from the circulating rules.

---

## Proposed integration: three-layer gate

Keep the circulating rule structure but replace its **fatal-high layer** with
the Atamai ceilings, so the story becomes:

| Layer | Source | Semantics |
|---|---|---|
| 1. Sentinel strip | [Quality checks](quality-checks.md) | `-9999`, bare `0`, … removed before any range test |
| 2. Warning band | GC Upload Rules (kept, with the noisy highs renegotiated) | "review this value" — never blocks |
| 3. Plausibility ceiling | **Atamai** (with fallbacks) | "physically impossible" — blocks upload |

Concretely:

- **Fatal high** becomes `min(GC fatal high, Atamai ceiling)` per analyte — in
  practice the Atamai number, since it is lower almost everywhere.
- **Warning high** stays from the GC rules for now (see *clashes* below for the
  ones that must move).
- **Warning low + fatal low** stay exactly as circulated — Atamai has nothing
  on the low side.
- **Universal fatal** `> 1,000,000 ppm` (elements) and `> 100 wt%` (oxides)
  remain as the backstop for analytes Atamai does not cover (43 GC elements —
  the synthetic/noble-gas filler rows — have no Atamai row).

### The ore-grade second dimension

12 Atamai rows carry an ore-grade threshold (`pct_ore_grade_only`):

| Analyte | Atamai ceiling | ore-grade from | GC warn high today |
|---|---|---|---|
| Ag | 870,000 ppm | 100 ppm (0.01 %) | 5,000 |
| As | 460,000 | 10,000 (1 %) | 22,000 |
| Co | 360,000 | 1,000 (0.1 %) | 48,000 |
| Cr | 500,000 | 50,000 (5 %) | 10,000 |
| Cu | 800,000 | 10,000 (1 %) | 50,000 |
| Mo | 600,000 | 1,000 (0.1 %) | 600,000 |
| Ni | 650,000 | 10,000 (1 %) | 10,000 |
| Pb | 870,000 | 10,000 (1 %) | 5,000 |
| Sb | 720,000 | 50,000 (5 %) | 100 |
| Sn | 800,000 | 10,000 (1 %) | 500 |

This solves the draft review's question 2 *and* 7 in one move: instead of
debating a single warning number, adopt the Atamai pair —
**above the ore-grade threshold the value is flagged "ore-grade / check unit"
(warning), above the mineral ceiling it is fatal**. That gives the QC report a
third outcome ("legitimate ore") instead of forcing every ore value into either
silence or alarm.

## Where the two tables clash — expert decisions needed

### A. Elements where Atamai is much **tighter** (would block real data)

17 matched elements: Atamai ceiling below GC warning high — adopting it as fatal
would block values that the current rules merely warn about. The dangerous ones:

| Element | GC warn high | Atamai ceiling | Assessment |
|---|---|---|---|
| **Zr** | 510,000 | 50,000 (5 %) | Atamai is bulk-rock reasoning ("bulk rock < 300 ppm"). Heavy-mineral sands reach 40 % Zr as zircon concentrates. **Keep GC fatal 1,000,000; use 50,000 only as ore-grade warning.** |
| **Be** | 360,000 | 5,000 (0.5 %) | Same pattern — beryl concentrates exceed 5 % Be. |
| **Sc** | 20,000 | 10,000 | thortveitite concentrates exceed this. |
| **Cs** | 2,000 | 50,000 | Atamai *looser* here — fine. |
| B, F, Ga, Li, Na, P, S, Si, Ca, Eu, Ir, Os, Rh, Ru | roughly comparable (ratio 0.5–1.0) | | Adopt Atamai as fatal; GC warning may stay inside it. |

Minor PGE/pb differences (Ir 10 → 5 ppb, Rh 100 → 5 ppb, Os 100 → 2 ppb) are
harmless for bulk-rock but tight for ore — treat as warning-only.

### B. Elements where Atamai is much **looser** (the draft's noise problem, solved)

52 elements — every one the draft review flagged — becomes a non-issue when the
*warning* stays but the *fatal* moves to the mineral ceiling:

- Fe 55,000 → 900,000 fatal; **warning can then rise to ~150,000–200,000** as
  the draft suggested, or stay at 55,000 as an informational ore-grade flag
  using the Atamai ore threshold (1 % for Ni/Cu/Pb/Zn-class analogues).
- Pb, Zn, Ag, Cu, Sb, Sn, W — exactly the analytes the draft called "will fire
  on real ore". With Atamai ceilings as fatal, warnings can stay where they are
  and be documented as *"possible mineralisation, check unit"* instead of
  *"anomalously high"*.

### C. Units and code mismatches (mechanical, fix before adopting)

| Issue | Detail | Action |
|---|---|---|
| **Au in ppb** | Atamai: 200,000 ppb = 200 ppm — same number as GC, just unit-labelled ppb. Verify intent: if the ceiling is really 200 **ppb** (0.2 g/t), it would flag any ore. | Confirm with Atamai; expect 200,000 ppb = 200 ppm. |
| **Hg in ppb** | 100,000,000 ppb = 100 % — label conversion artefact; ceiling is effectively 100 %. | Keep as 100 %. |
| **ppb rows (Ir, Os, Pd, Pt, Rh, Ru, Re, OsIr)** | Atamai ceilings in ppb are orders of magnitude *below* GC's (e.g. Pd 50 ppb vs GC 10 ppm). Bulk-rock correct but would flag any PGE ore. | Treat as ore-grade warnings, not fatals. |
| **`La2O1`** | Atamai note says it themselves: *"appears to be a typo for La2O3"*. | Map to La2O3, 25 wt%. |
| **`FETO3`** | = FeOT / Fe2O3(T) total iron. | Map to LithoSurfer's `FeOT` name. |
| **`S2O`** | Atamai: *"treat max as 100% pending clarification"*. | Keep GC fatal 100 %, ignore ceiling. |
| **`YFe3`** | Atamai: *"unusual analyte code, may be lab artifact"*. | Do not adopt until provider confirms. |
| **Carbonates as analytes** | `CaCO3`, `MgCO3`, `FeCO3`, `MnCO3` — valid for carbonate-chemistry surveys but not in LithoSurfer's `LOxide` list. | Park; only adopt if/when the vocabulary adds them. |

### D. Oxide layer — mostly redundant, keep it simple

40 of Atamai's 52 oxide rows match GC oxide names; all GC oxide rules are a
plain `> 100 wt%` fatal. The Atamai ceilings are lower for ~30 of them
(e.g. CeO2 48 %, Dy2O3 8 %, K2O 67 %, MnO 84 %, P2O5 46 %, WO3 82 %) —
but those ceilings encode *bulk-rock* reasoning that would flag genuine
mineral separates. **Proposal: keep the `> 100 wt%` fatal for all oxides
(including Total's 90–105/130 rule), and use Atamai's per-oxide numbers only
as optional warning reference values, not as fatals.**

This also cleanly sidesteps the non-standard names (`FeO2`, `Br_Raw`…) the
draft already questions — those stay in the GC list untouched.

### Also carried over from the draft review

- **Ag < 0.5 ppm / Co < 30 ppm warning lows** — the Atamai table gives no
  low-side support either way. Keep the draft recommendation: drop both.
- **Synthetic/noble-gas rows** (Ac…Ts): no Atamai coverage — they only ever had
  GC filler warnings. Recommendation stands: drop from the live gate.
- **Total 90–105 warning / 130 fatal**: unchanged; Atamai has no Total row, so
  the open question against [quality-checks](quality-checks.md) remains open.

## What adopting this would mean in practice

1. **No change to [Quality checks](quality-checks.md)** — sentinels, closure,
   spectrography and conversion checks are orthogonal and stay.
2. `thresholds.md` gets restructured from "circulating table + remarks" to the
   three-layer table above once experts sign off; this proposal page is the
   staging area for that edit.
3. Implementation follows the same order the draft already prescribes:
   strip sentinels → apply warnings → apply fatal ceilings. The only new
   machinery is the ore-grade flag (a third output state, not a threshold type).
4. Nothing here removes the flag-don't-fix rule: a ceiling breach is still a
   flag with a reason, and for the 12 ore-grade analytes the default action is
   *note*, not *block*.

## Open questions for Atamai / experts

1. Are the ppb rows (Au, Hg, PGEs) meant as ppb or were they converted from ppm?
2. Should `La2O1`, `FETO3`, `S2O`, `YFe3` be treated as typos of known analytes
   (and if so, which)?
3. Do the carbonate analytes (CaCO3, MgCO3, FeCO3, MnCO3) reflect an upcoming
   `LOxide` vocabulary extension?
4. Is the ore-grade threshold list (12 analytes) intended to be exhaustive, or
   should the same % ore-grade logic extend to the REE/Be/Zr rows whose
   ceilings are bulk-rock-derived?
5. Licence/attribution: can the Atamai-derived ceilings be published in the
   public user documentation with credit, or only used internally?
